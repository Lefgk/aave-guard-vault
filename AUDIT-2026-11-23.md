## 4. Findings

### [L-1] `repay` refunds the vault's whole USDC balance to the caller — Acknowledged

**Where:** `_repay()` lines 328-329: `leftover = IERC20(usdc).balanceOf(address(this)); safeTransfer(msg.sender, leftover)`.
**Impact:** The vault normally holds no idle USDC, but any USDC that lands there (owner `withdraw(usdc, to = vault)`, an allowlisted recipient set to the vault, a donation or mis-sent transfer) can be taken by anyone for a 1-wei `repay`. Needs an owner mistake or a third party's own transfer, so Low. PoC: `test_L1_repaySweepsIdleUsdcToCaller` (stranger takes 1,000 USDC for 1 wei).
**Recommendation:** refund only `pay - repaid`, and reject `to == address(this)` in `withdraw`/`withdrawETH`/`setRecipient`. audit-kb: Ackee / IPOR Fusion, "User-controlled refund list allows sweeping any ERC20 balances held by the zap contract" (high in that context, where the zap routinely held balances).

### [L-2] WETH withdrawn to the vault address is stuck — Acknowledged

`withdraw(weth, address(vault), x)` is allowed; `supply()` pulls from `msg.sender` and `wrapAndSupplyETH()` only wraps native ETH, so the WETH has no way out. PoC: `test_L2_wethWithdrawnToVaultIsStuck`. Fix with the same `to != address(this)` check, or a `supplyIdle(asset)` owner function.

### [L-3] Owner cannot withdraw collateral while HF < floor — Acknowledged

`withdraw`/`withdrawETH` call `_assertFloor()`, so after a price drop (HF between 1.0 and the floor) the owner must repay before touching any collateral, even to move it. Intended safety behaviour, but the dapp should say so.

### Info

- **I-1** Per-agent `outstanding` is principal only and is zeroed on revoke; Aave interest accrues on the shared position. Accounting/UX only (documented in NatSpec).
- **I-2** `variableDebtUsdc` may be zero (factory allows it). Then `usdcDebt()` reads 0 and `repay` relies on Aave capping the repayment, with the excess refunded. Works, but set it on deploy (DeployConfig does).
- **I-3** If USDC blacklists the vault, borrow/repay stop working (inherent to USDC). A blacklisted recipient only makes that agent's borrow revert.
- **I-4** `renounceOwnership()` (inherited) would strand the collateral; consider overriding it to revert.
- **I-5** HF floor relies on Aave's oracle and `getUserAccountData`; no extra oracle surface in this contract.

## 5. Refuted leads (checked, not issues)

- Budget refill via repay or `repayFor`: `borrowedInWindow` is gross, never reduced (`testFuzz_repayDoesNotRefillBudget`).
- Stale permissions after revoke/re-grant: budgets and allowlists are keyed by `(agent, epoch)` (`testFuzz_revokeWipesBudgetAndRecipients`).
- Borrow below the HF floor at any collateral price: atomic post-borrow check (`testFuzz_borrowNeverBelowFloor`, plus existing invariant `invariant_hfFloorHonored` and fork `test_fork_hfFloorBlocksOversizedBorrow`).
- Theft/inflation via `repayFor`: payer only spends own USDC, debt drops by exactly that (`testFuzz_repayForCannotStealOrInflate`).
- Reentrancy: all state-changing entry points are `nonReentrant`; ETH sent last in `withdrawETH`; USDC has no hooks.
- Period-window math (`_currentWindow` divide-then-multiply): intentional alignment to period boundaries.

## 6. Slither triage

`divide-before-multiply` (window alignment, intended), `incorrect-equality` (zero checks), `unused-return` (only HF needed), `missing-zero-check` (guardian zero = none; debt token optional), `timestamp`, `low-level-calls` (ETH send with success check). All false positives / by design.
